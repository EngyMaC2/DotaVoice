# DotaVoice · Command Voice Bridge

**Настольное приложение** для голосовой связи в Dota 2. Оно следит за матчем
через Game State Integration (GSI), автоматически подключает вас к голосовой
комнате матча, делит игроков на два изолированных канала — **Силы Света**
(Radiant) и **Силы Тьмы** (Dire) — применяет мут на стороне сервера и ведёт
прозрачный оверлей поверх игры, который показывает, кто говорит, кто в муте и за
какую сторону играет каждый участник.

Управляет всем этим агент [OpenHands](https://docs.openhands.dev/): каждому
матчу соответствует ровно один диалог агента, а его инструменты
(`create_voice_channels`, `sync_roster`, `move_player`, `set_mute`, `set_deafen`,
`get_session_state`, `end_session`) фактически меняют голосовые каналы и оверлей.

```
Игра (GSI) ──HTTP──▶ /gsi ──▶ Оркестратор ──▶ агент OpenHands ──▶ голосовой бэкенд (каналы, мут)
                                  │                                      │
                                  └──▶ шина событий ──WS──▶ /ws/overlay ──▶ прозрачный оверлей
```

## Установка и запуск приложения

Приложение — это настоящая настольная программа: мастер первоначальной настройки,
главное окно с управлением и прозрачный оверлей. Браузер не нужен.

### Быстрый путь (Windows)

1. Запустите `install.bat` — он поставит приложение и положит ярлык **DotaVoice**
   на рабочий стол и в меню «Пуск».
2. Двойной клик по ярлыку — приложение открывается как обычная программа.

### Настоящий установщик (.exe и .msi)

Если нужен привычный вид «обычного приложения» — отдельный `DotaVoice.exe` и
установщик `DotaVoice-<версия>.msi` (Windows Installer, с ярлыками на рабочем
столе, в меню «Пуск» и записью в «Программы и компоненты»), запустите:

```bat
build_windows.bat
```

Сборка требует Python 3.12+ и интернет для зависимостей; для `.msi` нужен
[WiX Toolset v3](https://github.com/wixtoolset/wix3/releases) (`winget install WiXToolset.WiXToolset.3`).
Результат — в папке `dist`:

```
dist/DotaVoice.exe           готовое приложение (один файл, без консоли)
dist/DotaVoice-0.2.0.msi     установщик
```

Если WiX не установлен, `.exe` всё равно собирается и работает сам по себе.

### Linux и macOS

```bash
./install.sh          # Linux / macOS
install.bat           # Windows (из исходников)
```

Установщик создаёт отдельное виртуальное окружение, ставит зависимости и добавляет
ярлыки запуска — на рабочем столе и в меню приложений/«Пуск». После этого:

```bash
dotavoice-gui         # запустить приложение (или ярлык DotaVoice)
```

При первом запуске открывается **мастер настройки**:

1. **Steam и Dota 2** — папки находятся автоматически (реестр Windows, типовые
   пути, `libraryfolders.vdf`), читается профиль Steam из `loginusers.vdf`,
   показывается список аккаунтов. Папку можно указать вручную.
2. **Голос** — имя в матче и устройства микрофона/вывода.
3. **Оверлей** — включение, положение на экране, режим «поверх всех окон».

На этом шаге приложение **само создаёт нужный файл** — `gamestate_integration_dotavoice.cfg`
в каталоге `game/dota/cfg/gamestate_integration` вашего профиля Dota 2. Вам не нужно
копировать файлы руками.

Дальше всё автоматически: начинается матч — приложение **само подключается** к
голосовой комнате этого матча, распределяет участников по сторонам и показывает
оверлей. Перезапуск игры или кратковременный обрыв связи сессию не разрывают.

Пошаговое руководство для пользователя — в [docs/desktop.md](docs/desktop.md).

### Что в главном окне

- список активных матчей, оба командных канала и игроки в них;
- индикатор говорящего, кнопки **заглушить** и **сменить команду** у каждого игрока;
- кнопка **push-to-talk** (по умолчанию клавиша `V`) и переключатель оверлея;
- **настройки**: папки Steam/Dota 2, установка файла интеграции, устройства звука,
  голосовой бэкенд, положение оверлея.

### Как настольное приложение соотносится с сервисом

Внутри приложения работает тот же HTTP/WebSocket-движок, что и в сервисном
режиме: он поднимается в фоновом потоке на локальном порту, а интерфейс
обращается к нему. Поэтому те же страницы (`/`, `/overlay`, `/ws/overlay`,
`/healthz`) остаются доступны, и мост можно запустить и как обычный сервис:

```bash
python -m dota_voice                 # только сервис, на http://0.0.0.0:12000
```

## Почему «одна катка без разрывов»

Сессия привязана к стабильному `match_id` игры, а не ко времени запуска процесса.
Из этого следует:

- Повторное `match_started` для того же `match_id` подхватывает уже существующую
  сессию и диалог агента; вторая пара каналов никогда не создаётся.
- Если клиент игры перезапустился, GSI снова пришлёт тот же `match_id`, и агент
  подхватит сессию (при этом счётчик переподключений увеличится).
- Каналы создаются только тогда, когда у сессии их ещё нет, а бэкенд Discord
  дополнительно переиспользует каналы по имени, поэтому даже полный перезапуск
  сервиса не может их продублировать.
- Сессия, которая замолчала, разбирается только после
  `DOTAVOICE_SESSION_GRACE_SECONDS` — это окно, в течение которого
  переподключающийся клиент всё ещё распознаётся.

## Быстрый старт для разработки

```bash
pip install -e ".[dev,agent,audio]"
cp .env.example .env                 # необязательно; есть разумные значения по умолчанию
python -m dota_voice                 # поднимается на http://0.0.0.0:12000
```

Затем откройте:

- `http://localhost:12000/` — панель управления (активные катки, команды, муты)
- `http://localhost:12000/overlay` — прозрачный оверлей (для OBS Browser Source)
- `http://localhost:12000/healthz` — состояние и метрики

### Попробовать без игры

Симулятор отправляет реалистичные полезные нагрузки GSI в запущенный мост:

```bash
python -m scripts.simulate --scenario basic      # старт, смена команды, конец
python -m scripts.simulate --scenario reconnect  # один и тот же match_id, три раза
python -m scripts.simulate --scenario mute       # мут на сервере + индикатор речи
```

Есть также полностью локальное демо (без сети и без игры), которое подключает
настоящего агента и печатает итоговое состояние голоса на каждом шаге:

```bash
python -m scripts.demo
```

## Подключение Dota 2

Файл интеграции создаёт само приложение в мастере настройки (или кнопкой
«Установить файл интеграции» в настройках). Вручную это выглядит так:

1. Скопируйте конфиг GSI в папку Dota 2:

   ```
   gsi/gamestate_integration_dotavoice.cfg
     -> <Steam>/steamapps/common/dota 2 beta/game/dota/cfg/gamestate_integration/
   ```

2. Задайте один и тот же токен в двух местах:

   - в конфиге: `"auth": { "token": "..." }`
   - в приложении: поле «Токен GSI» или `DOTAVOICE_GSI_TOKEN`

   Если токен пустой, проверка пропускается (только для разработки).

3. Запустите приложение и начните матч (или смотрите его как наблюдатель). Матч
   появится в окне и на оверлее в течение секунды, а приложение само подключится к
   голосовой комнате этого матча.

Конфиг запрашивает только `provider`, `map`, `player`, `hero` и `allplayers` — этого
достаточно, чтобы определить матч и состав, и ничего из того, что меняется каждый
кадр. Блок `allplayers` нужен, чтобы у наблюдателя был полный состав обеих команд.

## Настройка

Все параметры берутся из переменных окружения (см. `.env.example`):

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `DOTAVOICE_PORT` | `12000` | HTTP-порт |
| `DOTAVOICE_GSI_TOKEN` | _(пусто)_ | Общий секрет, сверяется с `auth.token` из GSI |
| `DOTAVOICE_STORE` | `memory` | `memory` или `redis` (переживает перезапуск сервиса) |
| `DOTAVOICE_VOICE` | `relay` | `relay` (встроенный голосовой сервер), `memory` (только состояние) или `discord` |
| `DOTAVOICE_VOICE_RELAY_URL` | _(пусто)_ | Адрес внешнего голосового сервера; пусто = встроенный на `DOTAVOICE_PORT` |
| `DOTAVOICE_DISPLAY_NAME` | _(пусто)_ | Имя в голосовом канале |
| `DOTAVOICE_INPUT_DEVICE` / `DOTAVOICE_OUTPUT_DEVICE` | _(пусто)_ | Устройства звука (пусто = системные) |
| `DOTAVOICE_SESSION_GRACE_SECONDS` | `900` | Окно простоя до разбора сессии |
| `DISCORD_BOT_TOKEN` / `DISCORD_GUILD_ID` | _(пусто)_ | Данные доступа к голосовому бэкенду Discord |
| `DISCORD_USER_MAP` | `{}` | JSON-словарь: игрок в игре -> id пользователя Discord |
| `LLM_API_KEY` | _(пусто)_ | Задайте, чтобы включить необязательный слой рассуждений |

## Голосовые бэкенды

**`relay`** (по умолчанию) — собственный голосовой сервер на UDP, встроенный в
приложение. Он создаёт по комнате на каждый `match_id`, сам распределяет
участников по сторонам и применяет мут и оглушение **на сервере**: заглушённое
аудио просто не пересылается. Комната Света и комната Тьмы полностью изолированы.
Само приложение подключается к комнате как обычный участник, поэтому слышит
собеседников и показывает, кто говорит. Если задать `DOTAVOICE_VOICE_RELAY_URL`,
тот же протокол можно направить на внешний сервер — тогда один узел обслуживает
несколько игроков. Настоящий звук (Opus + устройства ввода/вывода) включается
зависимостями из `.[audio]`; без них клиент работает в режиме «только состояние»
и всё равно корректно подключается и показывает говорящих.

**`p2p`** соединяет игроков напрямую, без общего сервера: они находят друг друга
по `match_id` в локальной сети и шифруют голос end-to-end (XChaCha20-Poly1305).
Пир с противоположной стороны не связывается с вами вообще, мут — локальный и
односторонний, а аккаунты не нужны. Включается через `DOTAVOICE_VOICE=p2p`.
Подробности — в [docs/p2p.md](docs/p2p.md).

**`memory`** моделирует каналы и голосовое состояние каждого игрока внутри
процесса. Именно на нём работают демо и часть тестов.

**`discord`** использует REST API Discord, чтобы создать два командных канала,
перемещать участников и применять флаги mute/deafen. Нужно знать две вещи:

- Бот, работающий только через REST, не может перетащить отключённого
  пользователя в канал. Игроки должны уже находиться в голосовом канале на
  сервере (хорошо подходит общий «лобби»-канал); после этого мост переводит их в
  нужный командный канал.
- Бот, работающий только через REST, не получает события речи из шлюза Discord.
  Поэтому индикаторы речи приходят со стороны игры/клиента через
  `POST /api/sessions/{match_id}/speaking`.

Чтобы добавить другой бэкенд (TeamSpeak, WebRTC SFU), реализуйте протокол
`VoiceBackend` в `dota_voice/voice/base.py` и возвращайте его из
`build_voice_backend`.

## HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/gsi` | Приёмник GSI от Dota 2 (с проверкой токена) |
| `GET` | `/ws/overlay` | WebSocket-поток событий для оверлея |
| `GET` | `/overlay` | Страница прозрачного оверлея |
| `GET` | `/` | Панель управления |
| `GET` | `/api/sessions` | Снимки активных сессий |
| `GET` | `/api/sessions/{match_id}` | Снимок одной сессии |
| `POST` | `/api/sessions/{match_id}/mute` | `{player_id, muted}` |
| `POST` | `/api/sessions/{match_id}/deafen` | `{player_id, deafened}` |
| `POST` | `/api/sessions/{match_id}/move` | `{player_id, team}` |
| `POST` | `/api/sessions/{match_id}/speaking` | `{player_id, speaking}` |
| `POST` | `/api/voice/transmit` | Вкл/выкл передачу микрофона (push-to-talk) |
| `POST` | `/api/voice/deafen` | Вкл/выкл локальное оглушение |
| `POST` | `/api/sessions/{match_id}/end` | Завершить сессию |
| `GET` | `/api/security` | Инварианты безопасности, флаги политики, автозапуск |
| `POST` | `/api/security/audit` | Проверить конфигурацию на утечки и небезопасные флаги |
| `GET`/`POST` | `/api/security/autostart` | Состояние автозапуска / включить-выключить |
| `POST` | `/api/security/update/check` | Проверить подписанный манифест обновления |
| `GET` | `/healthz` | Состояние и метрики |

## Инструменты агента

| Инструмент | Действие |
|---|---|
| `create_voice_channels` | Создать/переиспользовать два командных канала (идемпотентно) |
| `sync_roster` | Разместить каждого игрока в канале его команды |
| `move_player` | Перевести одного игрока в канал команды |
| `set_mute` / `set_deafen` | Мут / оглушение игрока на стороне сервера |
| `get_session_state` | Прочитать фазу, составы, муты, счётчик переподключений |
| `end_session` | Пометить сессию завершённой, уведомить оверлей, убрать каналы |

Исполнители инструментов синхронные (требование SDK), но стек голоса и оверлея
асинхронный, поэтому каждый рантайм возвращается на цикл событий сервиса через
`MatchSessionRuntime.run_sync`. Работа агента и инструментов всегда выполняется в
рабочем потоке, поэтому цикл событий не блокируется.

## Безопасность игрока и аккаунта

DotaVoice сознательно не выходит за рамки того, что Valve разрешает внешним
инструментам: он читает состояние только через официальный **Game State
Integration**, не трогает память и процесс игры, не автоматизирует игровые
действия и **никогда не спрашивает пароль Steam**. Оверлей — внешнее окно или
источник для OBS, а не хук внутри игры.

Обновления защищены от подмены: манифест подписан **Ed25519**, файл проверяется
по SHA-256, есть минимальная поддерживаемая версия, поэтапная раскатка и
возможность срочного отката.

Эти обещания не только описаны, но и закодированы: их можно проверить через
`GET /api/security` и `POST /api/security/audit`. Полный разбор — в
[docs/security.md](docs/security.md).

Автозапуск с системой включается по желанию и полностью обратим: запись в
`HKCU\...\Run` в Windows, `~/.config/autostart` в Linux, `LaunchAgents` в macOS.
Права администратора не нужны, системные каталоги не затрагиваются.

## Тесты

```bash
python -m pytest -q
```

Набор тестов работает с настоящим SDK OpenHands — реальные диалоги, реальное
выполнение инструментов, реальное сохранение — с подставным ключом, поэтому
сетевых вызовов не происходит. Он покрывает разбор GSI, идемпотентность сессий,
смену команды, mute/deafen, переподключение с переиспользованием, разбор
устаревших сессий, HTTP API, WebSocket оверлея и оба голосовых бэкенда (Discord
проверяется через подставной HTTP-транспорт — это единственное место, где
используется заглушка).
