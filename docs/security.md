# Безопасность игрока и аккаунта

Этот документ описывает, что DotaVoice делает и чего не делает с вашей игрой,
вашим Steam-аккаунтом и вашей сетью. Те же обещания закодированы в
`dota_voice/security/policy.py` — их можно проверить через API, а не только
прочитать здесь.

## Коротко

| Вопрос | Ответ |
|---|---|
| Читает ли память Dota 2? | Нет. Только официальный Game State Integration. |
| Внедряется ли в процесс игры? | Нет. Ни DLL, ни хуков, ни перехвата функций. |
| Управляет ли игрой за вас? | Нет. Никакой автоматизации ввода и игровых действий. |
| Нужен ли пароль Steam? | Нет. Приложение никогда его не запрашивает и не хранит. |
| Можно ли получить VAC-бан? | За сами механизмы — нет: GSI и внешний оверлей Valve разрешает. Риск появляется только если осознанно включить Steam SDR (см. ниже). |
| Безопасны ли обновления? | Да. Манифест обновления подписан Ed25519, файл проверяется по SHA-256. |

## Почему это VAC-безопасно

VAC реагирует на вмешательство в процесс игры: чтение памяти, внедрение
библиотек, перехват функций, автоматизацию ввода. DotaVoice не делает ничего из
этого.

* **Состояние игры** приходит по **Game State Integration** — официальному
  механизму Valve. Игра сама отправляет HTTP-запросы на локальный адрес с теми
  данными, которые вы разрешили в конфиге GSI. Приложение только слушает.
* **Оверлей** — это внешнее прозрачное окно (или источник для OBS). Оно рисуется
  поверх игры средствами операционной системы и не находится внутри её процесса.
  Именно внутренние оверлеи чаще всего приводят к блокировкам, поэтому политика
  считает внутренний оверлей ошибкой.
* **Автозапуск и GSI-конфиг** пишутся в пользовательские каталоги
  (`%APPDATA%`, `~/.config`, папка Dota 2), без прав администратора и без
  изменения самой игры.

## Риск Steam SDR (только по вашему решению)

Прямая передача голоса между игроками без общего сервера в идеале идёт через
**Steam Datagram Relay** (Steamworks). Это официальный сетевой API Steam, но он
требует Steamworks и подчиняется правилам Valve — вплоть до блокировки аккаунта
за нецелевое использование.

Поэтому SDR **выключен по умолчанию** и включается только явно:

```bash
DOTAVOICE_P2P_STEAM_SDR=1
```

Без этой переменной используется обычный UDP-транспорт, а попытка построить
SDR-транспорт завершается ошибкой `SdrUnavailable`. В отчёте о безопасности
включённый SDR отмечается отдельным предупреждением.

## Безопасность аккаунта Steam

Приложение **никогда** не спрашивает логин или пароль Steam:

* нет полей ввода для учётных данных;
* учётные данные не хранятся, не передаются и не пишутся в логи;
* `audit_config` отклоняет любую конфигурацию, где есть поле вида
  `steam_password`, `steam_login`, `api_key`, `secret` и т.п.

Единственный токен, который приложение хранит, — это **токен GSI**. Он
генерируется локально, нужен только для того, чтобы посторонний процесс не мог
подделать события игры, и не покидает вашу машину.

## Локальный мут

Мут в режиме P2P — **локальный и односторонний**. Когда вы мутируете игрока:

* вы перестаёте слышать его и перестаёте отправлять ему свой голос;
* для остальных ничего не меняется — это ваше личное решение;
* сервер не нужен, никто не может «размутить» вас против вашей воли.

Это осознанный выбор в пользу приватности: управлять чужим микрофоном нельзя.

## Изоляция команд

Игроки противоположной стороны **не связываются** с вами вообще: канал не
создаётся, если команда пира не совпадает с вашей. Даже если бы он создался,
аудио через границу команд не проходит — проверка стоит и на отправке, и на
приёме.

## Шифрование голоса

Голос шифруется end-to-end в режиме P2P:

* **XChaCha20-Poly1305** — аутентифицированное шифрование, то есть подмена и
  повреждение пакетов обнаруживаются;
* **X25519** — согласование ключей;
* ключ сессии выводится из `match_id` и одноразовых ключей сторон, поэтому
  посторонний, знающий только номер матча, не может расшифровать трафик;
* защита от повторов: повторно присланный пакет не будет проигран дважды.

Криптография сверена с официальными тестовыми векторами HChaCha20 и проверена на
совместимость с libsodium (PyNaCl) в тестах.

## Обновления

Автообновление — самая опасная функция в настольном приложении: подмена
обновления даёт выполнение кода у всех пользователей. Поэтому:

* манифест обновления **подписан Ed25519**, публичный ключ вшит в приложение;
* HTTPS сам по себе не считается достаточным — без корректной подписи обновление
  не применяется;
* у каждого файла закреплён **SHA-256**, он проверяется после загрузки;
* в манифесте есть **минимальная поддерживаемая версия**: слишком старые сборки
  обязаны обновиться;
* **поэтапная раскатка**: сборку можно отдать, например, 10% пользователей, и
  решение стабильно для конкретной установки;
* **откат вниз** возможен только если манифест помечен как срочный
  (`security_rollback`).

Приватный ключ подписи не должен лежать на машине разработчика: он живёт в
секретах CI или в HSM. `generate_keypair` пишет приватный ключ с правами `0600`
именно как напоминание об этом.

## Автозапуск

Автозапуск включается по желанию и всегда обратим:

* **Windows** — значение в `HKCU\...\Run`;
* **Linux** — файл `~/.config/autostart/dotavoice.desktop`;
* **macOS** — `~/Library/LaunchAgents/dev.dotavoice.DotaVoice.plist`.

Ничего не пишется в системные каталоги, права администратора не нужны. Выключение
удаляет ровно то, что создало включение.

## Проверка через API

```bash
# Инварианты, флаги политики, состояние автозапуска
curl http://127.0.0.1:3000/api/security

# Проверить произвольную конфигурацию
curl -X POST http://127.0.0.1:3000/api/security/audit \
  -H 'Content-Type: application/json' \
  -d '{"steam_password": "нет"}'

# Включить/выключить автозапуск
curl -X POST http://127.0.0.1:3000/api/security/autostart \
  -H 'Content-Type: application/json' -d '{"enabled": true}'

# Проверить подписанный манифест обновления
curl -X POST http://127.0.0.1:3000/api/security/update/check \
  -H 'Content-Type: application/json' \
  -d '{"manifest": "<json>", "public_key": "<base64>", "current_version": "0.2.0"}'
```
