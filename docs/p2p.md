# Голос напрямую между игроками (P2P)

Режим P2P переносит голос без общего сервера: игроки находят друг друга по номеру
матча и говорят напрямую, шифруя звук end-to-end. Он необязателен — по умолчанию
приложение работает через релей (см. `docs/`), а P2P включается одной переменной.

## Зачем

* **Нет сервера** — нечему падать и некому слушать. Голос не проходит через
  третью сторону.
* **Нет аккаунтов** — чтобы говорить с командой, не нужно регистрироваться.
* **Меньше задержка** — звук идёт напрямую, а не через релей.

## Как это работает

```
GSI: старт матча, match_id, ваша команда
        │
        ▼
  discovery ── multicast ──▶ список пиров по match_id (+ их команда)
        │
        ▼
  handshake ── X25519 + подтверждение ──▶ общий ключ сессии
        │
        ▼
  link ── XChaCha20-Poly1305 ──▶ голосовые кадры, мут, состояние «говорит»
```

1. **Обнаружение.** Каждый участник периодически рассылает в локальной сети
   небольшое объявление: хеш `match_id`, свою команду, порт и имя. Объявления
   других матчей игнорируются. Для сетей без multicast есть серверный релей —
   тогда поиск идёт через него.
2. **Рукопожатие.** Стороны доказывают друг другу, что знают один и тот же
   `match_id`, обмениваются одноразовыми ключами X25519 и выводят ключ сессии.
   Посторонний, который знает только номер матча, канал не откроет.
3. **Связь.** Голос шифруется XChaCha20-Poly1305. Каждый кадр нумеруется, поэтому
   повторы и перестановки отсекаются.
4. **Изоляция команд.** Пир с другой стороны не связывается с вами вообще. Даже
   если бы канал возник, аудио не пересекает границу команд — проверка стоит и на
   отправке, и на приёме.

## Включение

```bash
DOTAVOICE_VOICE=p2p
```

Дополнительно:

| Переменная | Значение по умолчанию | Что делает |
|---|---|---|
| `DOTAVOICE_P2P_GROUP` | `239.255.42.99:45678` | Адрес группы multicast для поиска в локальной сети. |
| `DOTAVOICE_P2P_STEAM_SDR` | `0` | Включить транспорт Steam SDR. Только осознанно — см. `docs/security.md`. |

В настольном приложении то же самое выбирается в мастере настройки: бэкенд
«напрямую между игроками».

## Мут

Мут локальный: он касается только вас. Вы перестаёте слышать игрока и перестаёте
отправлять ему свой голос, для остальных ничего не меняется. Сервер для этого не
нужен, и никто не может изменить ваш мут со стороны.

## Границы

* **Локальная сеть.** По умолчанию поиск идёт через multicast, то есть участники
  должны быть в одной локальной сети (типичный случай — компьютерный клуб или
  домашняя сеть). Для игры через интернет нужен релей или Steam SDR.
* **Нет качества-сервиса.** Без общего сервера нельзя гарантировать пропускную
  способность; на плохом канале качество будет ниже, чем через релей.
* **NAT.** Прямое соединение между разными домашними сетями обычно требует
  проброса портов. Это ожидаемо для серверлесс-модели.

## Приватность

* Номер матча не передаётся в открытом виде — только его хеш.
* Голос шифруется end-to-end; посредник (если он есть) видит лишь зашифрованные
  пакеты.
* Список участников виден только тем, кто знает номер матча.

## Тесты

```
python -m pytest tests/test_net_crypto.py tests/test_net_mesh.py tests/test_voice_p2p.py
```

Криптография сверяется с официальным тестовым вектором HChaCha20 и с libsodium
(PyNaCl); связь проверяется на настоящих UDP-сокетах.
